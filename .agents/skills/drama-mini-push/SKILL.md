# Drama Mini 推送

仅在 `drama-mini` Git 仓库执行。用户说“推送”时，按以下顺序处理本次修改；创建或调用本 skill 本身不代表立即推送。

1. 检查当前分支、远程、工作区与暂存区改动，确定“本次修改”的文件范围。区分用户原有改动和本次任务改动；范围不明确时先询问，不要使用 `git add .` 混入其他文件。
2. 阅读仓库根目录的 `CHANGELOG.md`。若不存在则创建。根据实际差异，用简短直白的中文记录本次修改点，不夸大未验证的效果，不重写历史条目。
3. 对照历史 changelog：若本次改动与已有记录所述行为、约定或状态不一致，列明具体条目和差异，等待用户确认如何记录或处理；没有历史记录时跳过此项。普通新增功能不算冲突。
4. 向用户展示 changelog 新条目、拟提交文件、当前分支和目标远程，明确等待用户确认推送。确认前不得提交或推送；若用户要求调整记录，先修改并重新展示。
5. 确认后仅暂存已核对的本次文件和 changelog，提交并推送到当前分支对应远程。禁止强制推送；远程拒绝或分支落后时停止，说明原因，不自动覆盖或合并远程历史。最后报告提交号、目标分支和推送结果。

遵守仓库 `AGENTS.md` 的验证要求；必要的验证应在请求推送确认前完成。
