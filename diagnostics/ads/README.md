# TikTok 广告真机诊断包

独立测试入口，使用真实 TikTok 短剧 SDK 和 `https://testservice.tkdrama.site`。普通 Mini 的入口、页面、广告等待和领奖流程不变，不需要服务端改动或 SQL。

```sh
npm run package:ad-diagnostics -- --app 7685293427067586568
```

输出 `.artifacts/ad-diagnostics/<AppID>/minis.zip`，不覆盖 `~/__TTMinis__/.../minis.zip` 的正常包。上传为对应应用的开发预览版本，扫描平台预览码。

1. 点击 **Connect with TikTok**，核对应用、UID、构建、操作系统、TikTok 版本及测试域名。
2. 从目录选择仍有锁定集的剧目，点击 **Read ad slots from test API**。广告位取自服务端当前用户 Offer 或启动配置，不在测试包中硬编码，也不展示播放授权或身份凭据。
3. **Create only**：设定次数（最多 20）和间隔，直接使用真实 SDK 创建，不调用 `show`。遇到同步异常或异步 `onError` 停止继续调度；迟到回调仍关联原创建序号。实例返回只说明取得 JS 实例，不证明初始化或加载成功。这是受控频控实验，不是生产预加载能力。
4. 本轮结束后保留页面等待迟到结果，点击 **Prepare sanitized JSON** 保存日志。创建专测可能留下未展示原生实例，因此必须关闭并重新打开 Mini 才开始下一轮，不依赖网页刷新清理原生状态。
5. **Create and show once**：每点击一次只创建、展示一条，手动关闭原生广告。无自动续看，无播放器，不调用领奖、广告展示事实或 `reportEvent`。展示未确认时仍保持互斥，迟到结果照实记录。

2026-10-22 复核[当前官方 SDK](https://connect.tiktok-minis.com/drama/sdk.js)：初始化错误会拒绝内部创建 Promise，公开 `show()` 会继续转发该拒绝，而原生 `onError` 的注册不一定向业务回调该创建错误。因此不能仅凭 `show_rejected + 30001` 认定用户取消。诊断包同时观察数值错误码的全局 `unhandledrejection`；该事件无公开实例标识，记录 `attempt=0` 和观察时累计创建数，不虚构具体失败实例。创建后可点 **Probe last instance via show()** 探测末个已有实例，不额外创建；初始化成功时可能打开一条真实广告。

记录 `attempt`、实际调用间隔、广告类型和广告位、回调来源、是否调用过 show、耗时、数值错误码／子码、脱敏消息和明确的 `isEnded`。未知结果不按成功处理，不将回调源不明的错误猜成创建频控。

按[短剧官方广告 SDK 文档](https://developers.tiktok.com/docs/en/minis-sdk-in-app-ads)，创建 API 的 `30001` 是同广告位请求过频，展示 API 的 `30001` 是未完播退出。官方未公开固定的“第几次必触发”阈值；测试结论必须附带应用、用户、客户端版本、请求节奏和观察窗口。连续二十次没有错误只能证明该轮未观察到，不能证明不限流。

日志在当前页面内存中，不上传自有广告统计，不保存 OpenID、VisitorToken、登录码或 SDK 原始对象。测试包只用于设备预览，不作为正常消费者包发布。

## 2026-10-22 真机记录

诊断包 `ad-diag-2` 在 iOS 平台预览中运行了同一广告位的 20 次创建调用，调度间隔为 200ms；随后仅对末个已有实例调用一次公开 `show()`，观察到广告展示和 `onClose(isEnded=true)`。该轮未观察到 `30001`，没有调用奖励结算接口。

这是一轮间隔调度实验，不是并发压测，也不能证明前十九个实例全部初始化成功。用户已停止后续频控测试，未执行更大批次或并发实验，未得到固定触发次数结论。代码保留最大 20 次及创建专测后需重进容器的边界；不要把它解释为官方预加载方案。
