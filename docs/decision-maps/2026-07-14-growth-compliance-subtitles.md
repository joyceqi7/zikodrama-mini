# 增长、合规与字幕决策图

> 历史决策记录：字幕相关决策已于 2026-09-12 被功能移除替代，现行行为见 [单语言验收](../single-language-release-checklist.md)。

> 历史决策记录。当前三工程边界、官方 Player 与 BytePlus 方案以工作区技术设计和各仓库 `AGENTS.md` 为准。

范围：协调消费者 H5（`drama-mini`）、消费者/运营 API（`drama-server`）和运营控制台（`drama-admin`）。

标准术语：

- **消费者 H5**：TikTok Minis 的观看体验。
- **运营控制台**：供已认证工作人员处理内容目录与媒体生命周期的界面。
- **字幕轨道**：关联到单集 VID 的一种语言的 VOD 字幕资源。
- **合规站点**：公开提供隐私政策、服务条款、支持和数据删除申请的页面。
- **发现查询**：由服务端执行的搜索或筛选请求；当前基于内存的标题和标签筛选不属于发现查询。

## #1：交付目标是什么？

前置依赖：无
类型：需求澄清

### 问题

四项能力是否应作为跨仓库、可用于生产的版本一次性交付，还是先交付可在本地运行的 MVP，再完成生产加固？

### 结论

已确定：分阶段完成可用于生产的交付。真实 TikTok 凭据与设备验收、生产环境法律配置，以及真实 BytePlus VOD 字幕上传仍是发布门槛，但不作为本地开发的依赖。

## #2：采用哪种 TikTok 分享能力？

前置依赖：#1
类型：调研

### 问题

消费者 H5 应使用哪一种现行 TikTok Minis 分享 API？如何进行能力检查？需要什么审核范围和请求字段？降级行为是什么？

### 结论

已确定：使用官方 TikTok Minis `minis.share` 事件和 `TTMinis.share`。适配器负责注册与主动分享，启动参数中的 `dramaId` 和 `episodeId` 均使用字符串，只允许 HTTPS 封面图片，并且仅在确认分享成功后触发消费者端 `share` 事件。浏览器开发环境使用 Web Share 或剪贴板作为降级方案。

## #3：发现功能的契约是什么？

前置依赖：#1
类型：需求澄清

### 问题

首个版本需要支持哪些可搜索字段、分类与榜单筛选、语言行为、分页模型和推荐区域？

### 结论

已确定：已认证接口 `GET /v1/discovery` 搜索按语言投影后的标题、描述和标签；支持精确标签筛选以及连载中/已完结状态筛选；使用有界的不透明游标。消费者端对请求进行防抖、丢弃过期响应，并支持加载更多。个性化排序和搜索索引不在本期范围内。

## #4：字幕的生命周期是什么？

前置依赖：#1
类型：需求澄清

### 问题

谁可以上传、审核、替换、发布、取消发布和删除单集字幕轨道？哪些轨道状态会阻止短剧发布？

### 结论

已确定：拥有 `content.media.upload` 权限的运营人员可在短剧未发布时上传 WebVTT、编辑标题、发布和取消发布轨道；拥有 `content.drama.read` 权限的人员可查看轨道列表。以 VOD 为权威数据源，新轨道初始状态为 `Unpublished`，播放接口仍只暴露已发布的 HTTPS 轨道。缺少字幕不会阻止短剧本身发布。

## #5：发布哪些合规主体信息和语言？

前置依赖：#1
类型：需求澄清

### 问题

应使用什么法律主体、管辖地区、公共域名、客服与隐私联系方式、生效日期、数据保留期限和首发语言，来替换合规站点中的模板内容？

### 结论

应用接入方案后续已调整：个人中心从 Bootstrap 获取当前应用的 HTTPS 合规站根地址，并连接隐私政策、服务条款和支持路由。合规站按应用维护法律主体、管辖地区、联系方式、日期及翻译，并自行完成语言协商；H5 不维护翻译，也不传 `lang` 查询参数。

## #6：锁定跨仓库契约

前置依赖：#2、#3、#4、#5
类型：调研

### 问题

四个仓库之间需要新增哪些 API 端点、权限码、事件载荷、公共配置值和兼容性规则？

### 结论

已按增量方式确定：新增 `/v1/discovery`；单集字幕查询、上传和更新路由；Bootstrap 下发应用级 `complianceBaseUrl`；TikTok 分享适配器；继续使用现有 `content.drama.read` 和 `content.media.upload` 权限。现有首页、播放和运营契约保持兼容，看似数字的平台标识符仍按字符串处理。

## #7：制定有序实施计划

前置依赖：#6
类型：需求澄清

### 问题

在保留现有未提交工作区以及各仓库专用验证命令的前提下，采用怎样的纵向功能切片顺序能够最大限度降低发布风险？

### 结论

已按以下顺序解决并执行：合规配置、发现 API 与界面、TikTok 分享、字幕服务与 VOD 适配器、运营控制台字幕功能，最后进行跨仓库验证和浏览器冒烟检查。现有未提交工作区已保留，且未创建提交。
