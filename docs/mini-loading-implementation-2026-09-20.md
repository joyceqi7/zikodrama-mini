# Mini 加载与切集优化实施记录

日期：2026-09-20。依据：`official-player-api-review-2026-09-20.md`。本记录描述已落地代码；研究稿中的“当前代码”是修改前快照。

## 已实施

1. 启动：登录和官方播放器准备并行，预热失败不阻断公开首页。明确的剧集深链延后首页预取，等待身份时展示目标入口加载态。HTML 保留环境 API 预连接，移除不区分路由的四个 fetch preload 和写死图片域名。
2. 公开请求：无请求体的 GET 不添加 JSON Content-Type，公开接口不携带 Authorization；增加 API 阶段耗时。
3. 图片：新增页面级共享资源队列，默认四个下载名额；按完整 URL 与版本去重。统一卡片 480px VOD 缩略图，不改写签名图。所有已返回轮播、热门、各分类、目录分页图片均登记，队列有优先级和防饥饿机制；15 秒超时，缩略图失败回退原图，失败资源允许后续重访重试。最多保留 128 个可淘汰终态资源；仍使用中的和待处理任务不强制丢弃。
4. 轮播：当前与下一张图片解码或失败兜底完成后才允许自动轮换，后台和离屏停止；支持动态数量，双项启用 rewind，保持手动操作。
5. 预加载：首页仅选择一个高概率候选，不等所有封面；显式触摸优先。全局 prepare 不再通过空列表更新清除场景。当前集首帧后交接 Feed 模式，只提交连续已验权窗口，不跨过锁集和未返回的授权。
6. 上下切集：保留单实例 playNext；进度条成为独立组件，内核时间变化不再导致整个剧场重绘。拖动结束才 seek，取消不 seek，切集清零；进度填充使用 transform。禁用重复的官方 progress 插件。保留原有滑动动画落定后切集行为。
7. 生命周期与刷新：保留已有广告/后台恢复验权和手动暂停语义；公开首页后台停留至少五秒后重取数据。目录按新游标重取已展开页数，避免刷新只剩第一页；新封面 URL 自动形成新资源任务。相同 URL 的内容替换仍服从 CDN/浏览器缓存规则，不能保证未版本化资源即时更新。
8. 观测：增加媒体信息缓存标记、字节命中、实际帧/估计帧区分、卡顿恢复、API 与构造器耗时、图片完成耗时。只观察官方媒体元素；不新增原生 video 或替代播放器。实际帧回调随切集/销毁取消，迟到回调不污染下一集。
9. 真机复测后的启动补强：播放器、历史和个人页改为路由级异步块，首页首块由约 488 KB 降至约 444 KB；图片预请求完成后断开内部 `Image` 与解码位图引用，避免最多 128 个资源在离开首页后继续占用内存。
10. 真机反馈的切集黑屏补强：恢复历史的剧集也展示首图，分集缺图时回退剧封；官方 `PLAYING` 不再直接等同首帧，无原生帧回调时等待有效时间更新。播放中 `WAITING` 用首图覆盖黑帧，恢复后等有效时间更新再撤。Feed 预加载按官方建议从后 3 集收敛为后 2 集，减少与当前播放争抢带宽。

## 第一轮真机结果

- 用户确认当时预览为已上传版本。从 Plotimo 启动页到首页骨架超过 10 秒，骨架到首批完整封面约再需 7 秒；本机直测 Sandbox 公开接口首字节约 1.1–2.7 秒，480px 图片约 0.7–2.9 秒，首轮慢点同时包含 TikTok 容器启动、接口及 CDN 图片。
- 轮播连续观察四次时，已展示的三张封面没有再出现单卡空白；期间捕获过一次 TikTok 黑色加载页后自动恢复，尚不能确认是容器重载还是预览环境切换。
- 首页进入第一集约 6 秒看到视频画面；进度拖动释放后正确跳转。剧集面板从第 1 集切第 2 集，约 0.8 秒已显示画面，没有封面空档。
- 第 2 集触发了激励广告并能关闭返回。后续测试时用户开始直接操作 iPhone，镜像先显示白屏再断开，因此白屏不能作为应用缺陷结论。
- 基于已确认的代码问题，随后补充路由拆包和图片预请求位图释放；完整 `make verify` 仍为 45 个文件、381 项 Vitest、30 项 Node 测试全部通过，并重新生成 22:00 测试包。
