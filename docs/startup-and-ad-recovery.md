# 投放入口与广告静默恢复

## 启动时序

首页、剧场和个人页均使用动态路由。投放入口提前加载剧场，不挂载或下载首页及 Swiper；正常进入首页时才加载首页代码。Web 构建会检查入口块和全部静态依赖，禁止首页或 Swiper 混入。

配置与身份安装并行。投放落地通过起播接口一次取得可信目标、入剧广告状态、VIP、目标海报及当前可用的播放决定；自然点选使用同一接口保留用户选集。详情消费同一主体和前台代次的结果，完整目录随后读取。首次入剧广告从剧集详情前台可见起累计时间，后台暂停，离开剧目或更换主体后重新计时。配置为 0 时，资格确认后立即发起当前需要的入剧广告。配置延迟时，时间与资格都满足后才按入剧广告、强制 VIP、逐集解锁的原顺序执行。强制 VIP 弹窗自己的倒计时仍在弹窗内独立执行。播放器初始化和首帧独立于广告计时；延迟期间只允许服务端授权的首集正片或试看，试看媒体进度仅用于限制授权范围及解锁后恢复。

独立普通版将后台相邻剧集授权查询安排在当前集出画后。首页卡片保持公开海报加载，实际点选时再用起播接口读取短期许可。

这项调整消除读取请求的串行依赖，不代表已确认 VIP 接口是线上瓶颈；具体延迟和首帧收益需要实际请求耗时与真机数据验证。

公开配置在 React 挂载前开始请求，启动与播放器共用这次请求。官方通道在配置、SDK 与完整身份就绪后准备宿主播放器构造器，与可信落地解析并行。确认独立通道后才加载 VePlayer 的包内代码与样式，宿主初始化和页面校验完成后配置许可。自然首页按下剧集卡片时准备剧场代码和目标海报，实际导航时立即准备所选播放器，和空闲定时器共享任务。投放直达提前准备剧场代码，目标确认后预取单张海报。两种通道的正片均继续等待服务端验权和业务门禁。

一次准备共享同一次 SDK 初始化结果，并将该结果传入独立适配器；SDK 失败后，即使公开配置较晚成功或错误传播与资源准备交错，也不能隐式启动第二次初始化。配置失败、身份失败和播放器失败保持原有诊断与显式恢复入口。

投放直达在 React 挂载前预连接 `https://vod.tkdrama.site`。自然入口在按下剧集卡片或直接导航到剧场时预连接，同一文档只插入一个匿名连接提示。提示本身不请求视频，连接是否能被实际取流复用取决于播放器使用的媒体域名和网络栈。

## 广告恢复边界

激励广告仅对明确未展示、已释放实例的 `50008`（子码或内部码）和 `11006` 活动冲突进行恢复。一次业务观看最多额外尝试一次，等待 5000 毫秒；参数在 `src/config/adPolicy.ts`。等待期间保留页面加载态和业务广告占用，不提前显示错误。第二次仍失败才交由现有错误提示和手动恢复入口处理。

恢复前持续复核前台、页面、主体及 Offer 意图；后台、离页、身份安装代次或业务条件变化都会取消旧意图。恢复不能绕过失败冷却或其他原生广告的互斥。恢复失败的 `50008` 继续暂停当前前台周期的自动展示，避免通过重新挂载页面无限探测。

`101150000 / 50010` 表示宿主拒绝非前台展示。确认未展示后释放本次实例，等到新前台周期才允许再次发起。入剧及强制 VIP 的既有恢复流程重新确认当前目标和资格。`121401` 表示宿主版本不支持激励广告调用，继续记录原始错误码，提示更新 TikTok，同一 SDK 实例不重复发起激励广告。

已展示后的错误、未确认的回调超时、能力缺失、用户取消和其他 SDK 错误不自动重拉。未知结果继续保留原生锁，迟到完播只写回原主体的原 ClaimID。只有 `isEnded === true` 才申请奖励。

两次原生尝试各有独立诊断 ID，保留原始错误码和脱敏详情；成功曝光、展示确认和奖励继续使用原业务 ClaimID，不因静默重试重复计数或新建奖励。

## 验证边界

自动化覆盖两种 provider 的慢 VIP 启动与强制门禁、静默恢复成功及耗尽、后台/离页/主体/Offer 作废、旧回调、未知结果和奖励归属。构建检查验证代码拆分。实际 TikTok 容器的恢复概率和首帧收益仍需新版 iOS/Android 真机验收；宿主持续拒绝无法由客户端保证消除。
