# 官方 Player 首帧体验策略

更新日期：2026-09-03

项目不承诺物理意义上的 0 ms 首帧。当前体验策略是：目标剧集 Poster 保持到官方 Player 报告真实播放帧、同一实例使用 `playNext` 切集、相邻剧集提前完成业务授权，并保留核心播放诊断日志；不建设无人消费的 QoE 自定义事件通道。

TikTok 官方文档已经提供 Player 媒体预加载能力，但它要求 MP4/MSE 等明确前提。启用前必须通过目标 TikTok 客户端和 BytePlus 工作流真机验证；当前版本不自行猜测媒体 URL，也不以 DirectUrl 或 HTML `<video>` 实现预加载回退。

生产播放合同见 [TikTok Minis 官方 Player 接入](./tiktok-minis-official-player.md)。

## 2026-09-21：页内切集从头播放

按当前产品要求，播放页内上下切集、选集跳转及自动下一集均不恢复目标集的历史秒位置；切回本次入口集也从头播放。仅首次进入播放页保留本机续播。历史仍按应用和账号保存，不删除用户记录。

切集后不再发起历史位置 seek，也不因已有历史进入等待续播帧的状态；仍以目标实际首帧结束正常切源过渡。广告返回或暂停恢复若没有换集，不因此重置正在播放的位置。此规则优先于旧优化方案中“切集后恢复历史”的描述。
